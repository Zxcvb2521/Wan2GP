# AI Creator Studio — Portable Runtime

Runtime должен быть аппаратно-адаптивным. Нельзя привязывать дистрибутив к RTX 5060 Ti или к одной версии CUDA.

## Принцип

Приложение определяет оборудование при запуске и выбирает подходящий backend/profile:

- NVIDIA CUDA — основной GPU backend для Windows;
- AMD/Intel/другие GPU — поддерживаемые backend'ы, когда конкретная модель и PyTorch их поддерживают;
- CPU — обязательный fallback для функций, которые допускают CPU execution.

Приложение не должно требовать от пользователя самостоятельно устанавливать Python, CUDA Toolkit или FFmpeg.

## Профили производительности

Профиль определяется автоматически:

- **Высокая производительность** — достаточно VRAM для выбранной модели;
- **Сбалансированный** — сниженный размер/число шагов и memory optimizations;
- **Экономичный** — CPU/offload/меньшее разрешение там, где backend это позволяет;
- **Недоступно** — модель не запускается на данном оборудовании и UI объясняет причину.

VRAM является ограничением конкретной модели/задачи, а не минимальным требованием всего приложения.

## Архитектуры

Windows x64 — первый официальный target.

В дальнейшем runtime должен собираться отдельно для поддерживаемых target triples, а Tauri выбирает соответствующий sidecar/runtime для платформы. Tauri поддерживает platform-specific sidecar binaries с target-triple suffix. 

## Почему не один универсальный CUDA runtime

CUDA/PyTorch binary compatibility зависит от GPU и выбранной сборки PyTorch. Поэтому нельзя просто зашить «CUDA для RTX 5060 Ti» и объявить это универсальным runtime.

Вместо этого installer получает базовый CPU-safe runtime, а GPU acceleration поставляется как versioned hardware backend/profile. Это позволяет поддерживать разные NVIDIA поколения без привязки к конкретной карте.

## План distribution channels

1. Windows NVIDIA — основной пакет.
2. Windows CPU — облегчённый fallback.
3. Windows AMD/Intel — отдельный backend, когда тестовый набор моделей подтверждён.
4. Linux — отдельный target после стабилизации Windows.
5. macOS — отдельный target с Metal/MPS-совместимыми моделями.

Не все генеративные модели обязаны поддерживаться на каждом backend. UI должен показывать доступность каждой функции отдельно.
